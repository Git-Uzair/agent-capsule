## 1. Executive Summary & The "Vibe Coding" Distribution Crisis

The rise of generative AI coding assistants (Claude Code, Cursor, Kilo, ChatGPT, OpenCode, Gemini CLI) has sparked the **"Vibe Coding" revolution**: millions of non-programmers, domain experts, product designers, and hobbyists can now generate fully functional, sophisticated software purely by chatting with AI agents.

However, an acute **Distribution & Execution Crisis** has emerged:

```
+-----------------------------------------------------------------------------------------+
|                                 THE PARADOX OF VIBE CODING                              |
|                                                                                         |
|   CREATION (2026):                                                                      |
|   "Hey Claude, build me a lead scoring dashboard that parses LinkedIn CSVs."           |
|   ===> DONE IN 60 SECONDS.                                                              |
|                                                                                         |
|   DISTRIBUTION & RUNNING (1995-ERA FRICTION):                                           |
|   - "How do I send this to Bob?"                                                        |
|   - "Tell Bob to install Git, Node 22, Python 3.12, run npm install, pip install..."    |
|   - "Bob is on Windows without admin rights. Bob gets 'Command not found: node'."       |
|   - "Tell Bob to use Docker Desktop... Docker requires WSL2, Hyper-V, 4GB RAM."         |
|   - Bob gives up.                                                                       |
+-----------------------------------------------------------------------------------------+
```

### The Core Thesis
Software generated by AI agents must be **packaged by AI agents**, **distributed as a single self-contained atomic unit**, **executable with a single double-click on any desktop OS without prior setup**, and **immediately attachable to any recipient's AI agent via the Model Context Protocol (MCP)**.

We define **`agent-capsule`** (extension: `.capsule` or `.box`): an ultra-minimal, capability-sandboxed, single-file polyglot executable that marries:
1. **Cosmopolitan Libc / APE (Actually Portable Executable)** for native cross-platform double-click launching on Windows, macOS, and Linux without any pre-installed runtime.
2. **WebAssembly (WASI 0.2 / Component Model)** for secure, capability-gated, deterministic execution of agent code.
3. **SQLite + `sqlite-vec`** as the single-file virtual filesystem, relational database, and vector memory store.
4. **Model Context Protocol (MCP)** as the universal semantic bridge allowing any recipient LLM agent to inspect, execute, patch, and fork the capsule.

## 2. Why Docker & Existing Packaging Models Fail for AI Agents

| Packaging Paradigm | Why It Fails for Non-Technical Users & AI Agents |
| :--- | :--- |
| **Docker / OCI Containers** | • Requires Docker Desktop daemon, root privileges, and hypervisors (WSL2 on Windows, Linux VM on macOS).<br>• Heavy resource footprint (gigabytes of image layers, gigabytes of RAM).<br>• Opaque Linux filesystem layers; an AI agent cannot easily inspect, patch, or hot-reload single functions.<br>• Exposes raw network ports/sockets rather than semantic tool schemas (MCP). |
| **Anthropic MCP Bundles (`.mcpb`)** | • Only packages MCP server metadata into a `.zip`; does **not** include runtime sandboxing or platform-independent interpreters.<br>• Requires host system to already have Node.js, Python, or platform-specific native binaries installed.<br>• Headless by design; cannot double-click to open a human visual UI. |
| **OS-Specific Bundlers (AppImage, MSI, DMG)** | • Completely fragmented by operating system and CPU architecture (x86_64 vs ARM64).<br>• No built-in agent communication protocol (MCP).<br>• High packaging overhead; impossible for an LLM agent to synthesize and cross-compile on the fly. |
| **Language Single-File Executables (`bun compile`, PyInstaller)** | • OS-targeted (a binary compiled for Mac ARM64 will not run on Windows x86_64).<br>• High binary bloat (60MB - 120MB per app).<br>• Zero sandboxing; runs with full host user permissions. |

### 3.1 The Genesis Capsule (`capsule-genesis` / Capsule Studio)
The entry point to the ecosystem is a single, lightweight binary called **`capsule.exe`** (or `capsule` on Mac/Linux), weighing less than 3 MB:

2. **Instant Local Web Studio:** It starts an embedded HTTP server and opens the browser to a clean, visual creation canvas.
3. **Built-in Local Agent:** If the user has no existing AI agent harness, Genesis includes a lightweight local agent UI (powered by WebLLM/Ollama or user-supplied Anthropic/OpenAI API keys).

To eliminate the cold start problem for recipients:

* The web app concatenates the pre-compiled Cosmopolitan APE base runner with the ZIP payload and downloads a fully autonomous `.capsule` executable to the user's computer.

## 4. The Universal Sandboxed Polyglot: File Format & Architecture

```
+===================================================================================================+
|                                    AGENT CAPSULE FILE LAYOUT                                      |
+===================================================================================================+
| Offset (Bytes)       | Section Name              | Description                                    |
+----------------------+---------------------------+------------------------------------------------+
| 0x00000000           | MZ / PE Header            | DOS/Windows PE executable signature ("MZ")     |
| 0x00000040           | APE Boot Code             | Cosmopolitan polyglot bootloader (x86_64/ARM64)|
| 0x00000200           | ELF Header                | Linux Executable and Linkable Format header   |
| 0x00001000           | Mach-O Fat Wrapper        | macOS universal binary header (x86_64 + ARM64) |
+----------------------+---------------------------+------------------------------------------------+
| [Base Runner Binary] | Embedded WAMR Engine      | WebAssembly Micro Runtime (WASI 0.2 execution) |
| (~2.2 MB compiled)   | Embedded QuickJS-WASI     | Ultra-light JS/TS evaluation engine            |
|                      | Embedded Micro-HTTP Core  | Zero-dependency web server & WS daemon         |
|                      | Stdio JSON-RPC Router     | MCP stdio / SSE transport protocol handler     |
+----------------------+---------------------------+------------------------------------------------+
| [ZIP Central Dir /   | capsule.json              | Declarative contract & MCP tool schemas        |
|  Payload Archive]    | /src/                     | Wasm bytecode & source scripts (introspectable)|
|                      | /ui/                      | Static frontend assets (HTML/CSS/JS bundles)   |
|                      | app.sqlite                | Relational data, vector memory, sqlar blobs    |
|                      | signature.sig             | Ed25519 cryptographic publisher signature      |
+===================================================================================================+
```

### 4.1 Physical File Anatomy (APE Polyglot + ZIP)
* **Actually Portable Executable (APE):** Uses the structural overlap of the MS-DOS stub, Unix shell script header, ELF binary format, and Apple Mach-O format to create a binary that the kernel of Windows, Linux, and macOS all accept as a native executable.
* **ZIP Quine Tail:** The standard ZIP specification reads archive metadata starting from the *End of Central Directory (EOCD)* record at the **tail** of the file. Cosmopolitan binaries ignore appended data. Therefore:
  - The OS loader executes the front of the file (the APE runner).
  - The embedded runner opens `argv[0]` (itself) as a standard ZIP file to mount its internal filesystem.
  - Standard ZIP tools (`unzip`, 7-Zip, Python `zipfile`) can inspect or unpack the capsule directly.

### 4.2 Sandboxed Execution Engine (WAMR & QuickJS-WASI)
Running arbitrary AI-generated native binaries on a user's machine is dangerous. To ensure complete safety:
* The APE base runner never executes unmanaged native code from the payload.
* All application logic is stored in `/src/` as either **WebAssembly modules (`.wasm`)** or **JavaScript scripts (`.js`)** executed by an internal **QuickJS-WASI** engine.
* **Hardware-Enforced Memory Safety:** WebAssembly isolates all linear memory. Pointer errors or buffer overflows cannot corrupt host memory.

### 4.3 Embedded State & Memory Engine (SQLite + `sqlite-vec` + `sqlar`)
* Every capsule embeds SQLite compiled into the base runner.
* **Virtual Asset Storage (`sqlar`):** Large assets, icons, and blobs are queried directly via SQL tables without extracting to host disk.
* **Vector Agent Memory (`sqlite-vec`):** Capsules can perform local semantic search, embedding lookups, and long-term memory retrieval without external vector database dependencies (Pinecone, Chroma, etc.).
* **State Persistence:** When the capsule runs, state mutations are written atomically to an internal SQLite WAL or a companion `.capsule-data` file.

### 4.4 Dual-Transport Dispatcher (Human GUI vs Agent MCP Mode)

```
                            +--------------------------+
                            | Execution Entry (main()) |
                            +-------------+------------+
                                          |
                        +-----------------+-----------------+
                        | Check Flags & TTY Environment     |
                        +-----------------+-----------------+
                                          |
                 +------------------------+------------------------+
                 |                                                 |
                 v (No flags / Double-click)                       v (Flag: --mcp or piped stdio)
     +-------------------------------+                 +-------------------------------+
     | HUMAN GUI MODE                |                 | AGENT MCP MODE                |
     | 1. Bind ephemeral port (e.g.  |                 | 1. Read JSON-RPC 2.0 on stdio |
     |    127.0.0.1:49215)           |                 | 2. Handshake `initialize`     |
     | 2. Serve `/ui/` from ZIP      |                 | 3. Expose tools & resources   |
     | 3. Launch default OS browser  |                 | 4. Execute WASM tool calls    |
     | 4. Show Tray Icon / Web View  |                 | 5. Output JSON-RPC responses  |
     +-------------------------------+                 +-------------------------------+
```

## 6. Agent-to-Agent Introspection & Self-Evolution Protocol

Unlike closed containers, an Agent Capsule is **fully transparent and mutable by other AI agents**. Every capsule automatically embeds five system-level MCP tools:

```
+-----------------------------------------------------------------------------------------+
|                        BUILT-IN SYSTEM MCP TOOLS FOR AGENTS                             |
+-----------------------------------------------------------------------------------------+
| Tool Name                   | Description                                               |
+-----------------------------+-----------------------------------------------------------+
| `capsule_inspect_manifest`  | Returns the parsed `capsule.json` and capability limits.  |
| `capsule_read_source`       | Reads any source code or UI file from `/src/` or `/ui/`.  |
| `capsule_query_database`    | Runs a safe, read-only SQL query on the embedded SQLite.  |
| `capsule_patch_file`        | Hot-patches a script or asset within the running capsule. |
| `capsule_export_fork`       | Recompiles and exports a new standalone `.capsule` file.  |
+-----------------------------------------------------------------------------------------+
```

### Self-Evolution Lifecycle Walkthrough
1. **User Request:** Bob tells his AI agent: *"The `crm-lead-enricher.capsule` is great, but please add a tool that also calculates estimated revenue."*
2. **Introspection:** Bob's agent calls `capsule_read_source("src/calculator.js")`.
3. **Synthesis:** Bob's agent generates the new revenue estimation algorithm.
4. **Patch & Test:** Bob's agent calls `capsule_patch_file("src/calculator.js", newCode)` and tests it by calling the new MCP tool.
5. **Repack:** The agent calls `capsule_export_fork("crm-lead-enricher-v2.capsule")`.
6. **Result:** A brand new, self-contained, single-file capsule is born without needing any external build tools or compilers.

## 7. Security Architecture, Sandboxing & Capability Model

Because capsules will be shared peer-to-peer on social channels, messaging apps, and email, a strict security framework is non-negotiable:

```
                        [ Untrusted Capsule File ]
                                    |
                                    v
            +-----------------------------------------------+
            | 1. Cryptographic Signature Verification       |
            |    (Ed25519 public key verification)          |
            +-----------------------+-----------------------+
                                    |
                                    v
            +-----------------------------------------------+
            | 2. Manifest Capability Audit                  |
            |    (Inspects declared network & storage needs)|
            +-----------------------+-----------------------+
                                    |
                                    v
            +-----------------------------------------------+
            | 3. User Permission Consent Prompt             |
            |    "Capsule wants access to api.anthropic.com"|
            |    [ ALLOW ONCE ]   [ ALWAYS ALLOW ]  [ DENY ]|
            +-----------------------+-----------------------+
                                    |
                                    v
            +-----------------------------------------------+
            | 4. Hardware WASM Capability Sandbox (WAMR)    |
            |    - No access to host ~/.ssh, C:\, /etc      |
            |    - No arbitrary host shell execution        |
            |    - CPU & Memory quota limits enforced       |
            +-----------------------------------------------+
```

### Key Security Guarantees
1. **No Host Binary Execution:** Capsules cannot spawn `cmd.exe`, `powershell.exe`, or `/bin/bash` on the host machine.
2. **Granular Network Whitelist:** Network requests via WASI sockets are strictly intercepted; only domains declared in `capsule.json` and approved by the user are routable.
3. **No Unsandboxed Disk Access:** File operations are restricted to the capsule's internal virtual filesystem. Exporting files to the host (e.g. saving a PDF) requires the user's explicit OS file-dialog confirmation.

## 10. Technical Reference Blueprints & Code Examples

### 10.1 Polyglot Packager Algorithm (Python Reference)
The following reference script demonstrates how an AI agent packs an application into an Actually Portable Executable:

```python
"""
capsule_pack.py - Reference Capsule Packager
Concatenates the pre-compiled Cosmopolitan APE base runner with an application ZIP payload.
"""
import io
import zipfile
import json
import sys

def create_capsule(base_runner_path: str, manifest: dict, src_files: dict, ui_files: dict, output_path: str):
    # 1. Read the APE Base Runner (Cosmopolitan + WAMR + MicroHTTP)
    with open(base_runner_path, "rb") as f:
        base_binary = f.read()

    # 2. Build the in-memory ZIP archive
    zip_buffer = io.BytesIO()
    with zipfile.ZipFile(zip_buffer, "w", compression=zipfile.ZIP_DEFLATED) as zf:
        # Write manifest
        zf.writestr("capsule.json", json.dumps(manifest, indent=2))
        
        # Write source code & WASM binaries
        for path, content in src_files.items():
            zf.writestr(f"src/{path}", content)
            
        # Write UI assets
        for path, content in ui_files.items():
            zf.writestr(f"ui/{path}", content)
            
    zip_payload = zip_buffer.getvalue()

    # 3. Concatenate Base Binary + ZIP Payload
    with open(output_path, "wb") as f_out:
        f_out.write(base_binary)
        f_out.write(zip_payload)

    print(f"Successfully generated Agent Capsule: {output_path} ({len(base_binary) + len(zip_payload)} bytes)")

if __name__ == "__main__":
    sample_manifest = {
        "name": "hello-agent",
        "version": "1.0.0",
        "entrypoint": "src/main.js",
        "ui": "ui/index.html"
    }
    # Example usage
    # create_capsule("bin/libcapsule-base.com", sample_manifest, {...}, {...}, "hello.capsule")
```

### 10.2 MCP Stdio Dispatcher Loop (C / Pseudo-Rust Engine)
```c
/*
 * dispatcher.c - Main entrypoint for Agent Capsule runtime
 */
#include <stdio.h>
#include <string.h>
#include <stdbool.h>

extern void run_http_server(const char *zip_path);
extern void run_mcp_stdio_loop(const char *zip_path);

int main(int argc, char **argv) {
    const char *self_path = argv[0];
    bool mcp_mode = false;

    // Check if invoked with --mcp or if stdin is piped
    for (int i = 1; i < argc; i++) {
        if (strcmp(argv[i], "--mcp") == 0 || strcmp(argv[i], "--mcp-server") == 0) {
            mcp_mode = true;
            break;
        }
    }

    if (mcp_mode) {
        // Run as Headless MCP Server over JSON-RPC stdio
        run_mcp_stdio_loop(self_path);
    } else {
        // Run as Human Desktop GUI: Launch micro-HTTP server and open browser
        run_http_server(self_path);
    }

    return 0;
}
```

The **Agent Capsule Standard (`.capsule`)** solves the missing link in the generative AI era: bridging the gap between friction-free creation and friction-free distribution.

By unifying **Actually Portable Executables**, **WebAssembly sandboxing**, **SQLite local persistence**, and the **Model Context Protocol**, Agent Capsules make software as shareable and interactive as a PDF or an MP3, while giving AI agents full semantic capability to run, inspect, and evolve the code.
